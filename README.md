# 5G SA / SDR UAV Swarm — Proof-of-Concept Measurement Data

Raw measurement logs, tidy datasets, regenerated figures, and the Jupyter notebook behind the
paper **"An SDR-Based 5G SA Architecture for UAV Swarm C2: A Proof of Concept"** (Tebbe,
Giurgică, Sârbu, Scholl — submitted to ICASC 2026). This repository exists so the paper's
Reproducibility statement is backed by an actually-public source, not just a claim.

Nothing here is synthetic or estimated. Every number traces to a raw log file in
`raw_measurements/`, and every figure is regenerated by `notebook/kpi_pipeline.ipynb` — see
`data/PROVENANCE.md` for the exact source file and transformation behind each column and figure.

## What's in this repo

| Folder | Contents |
|---|---|
| `notebook/kpi_pipeline.ipynb` | Parses the raw logs, writes the tidy CSVs in `data/`, and draws every plot in `figures/`. Runs top to bottom with no external path dependency (paths are computed relative to the notebook's own location). |
| `raw_measurements/` | The two measurement campaigns underlying the paper's link-layer numbers (idle RTT, TCP/UDP throughput, RF/PHY indicators), plus a third campaign (a separate, non-portable n41 testbed) used only for the paper's preliminary range-context figure. Untouched original `iperf3` JSON output, `ping` text output, and lab report notes. |
| `data/` | Tidy CSVs derived from the raw files above, with `README.md` (schema) and `PROVENANCE.md` (source file + transformation per column, per figure). |
| `figures/` | Every KPI plot the notebook regenerates from `data/`, as vector PDF. |
| `paper_figures/` | The non-KPI images used directly in the paper: the two testbed node photos, the payload-components photo, and the concept diagram. |

## Which figures actually appear in the paper

The submitted paper is scoped tightly to a proof-of-concept (architecture + feasibility +
frequency agility), not an exhaustive characterization — that exhaustive characterization is a
companion paper, cited in the ICASC submission. Consequently the paper's own figures are the
**concept diagram, the two node photos, the payload-components photo, the field-deployment
photo, and one range-context plot** (`fig_rtt_vs_distance_n41.pdf`). The paper reports its idle
RTT, TCP/UDP throughput, and RF/PHY numbers in prose rather than as separate plots.

The remaining KPI plots in `figures/` (`fig_tcp_timeseries.pdf`, `fig_udp_sweep.pdf`,
`fig_ping_rtt.pdf`, `fig_rtt_vs_pktsize.pdf`, `fig_rf_phy.pdf`, `fig_drone_c2.pdf`) are kept here
for full transparency even though the paper itself doesn't display them — they're the same
campaign, just trimmed from the 6-page conference format.

## A note on `drone_c2.csv` / `fig_drone_c2.pdf`

These files record a 50-byte UDP stream at 10/50/100 packets per second — packet rates chosen to
be representative of typical drone telemetry/setpoint rates. **No MAVLink protocol traffic, and
no other drone command-and-control payload, was actually transmitted**; this is a synthetic
`iperf3` UDP profile at drone-like rates, not a live drone link. The paper text is precise about
this distinction; this file's legacy name predates that precision and is kept as-is so the
provenance chain in `data/PROVENANCE.md` stays traceable to the exact raw files.

## Regenerate everything

```bash
cd notebook
jupyter nbconvert --to notebook --execute --inplace kpi_pipeline.ipynb
```

This rewrites every CSV in `data/` and every PDF in `figures/` from the raw files in
`raw_measurements/`. Requires Python 3 with `pandas`, `matplotlib`, and `jupyter`.
